\section{Scammer4U Benchmark}
\label{sec:benchmark}

\subsection{Threat Model}
\label{sec:threat}
% CITE-TYPE: confused-deputy origin; indirect-prompt-injection surveys; web-agent autonomy / consumer-default deployment posture

We consider a web-browsing vision-language agent acting on behalf of a user who has provisioned it with a static profile of personally identifiable information (PII). The agent is issued a goal-directed task in natural language (e.g., \emph{apply for this job}, \emph{buy these headphones}) and proceeds without further user supervision through a Playwright-driven browser session, observing each page as a screenshot paired with a flattened DOM and acting through a fixed JSON action space.

The attacker controls one or more web origins reachable from the agent's task, including by redirecting the agent via email links, downloads, or hyperlinks rendered on otherwise plausible pages. The attacker may serve arbitrary HTML, JavaScript, CSS, page copy, and chat content; embed instructions for the agent in visible text, hidden DOM, or simulated system messages; and operate endpoints to which the agent may POST data. The attacker cannot tamper with model weights, modify the user profile, intercept TLS, poison DNS, or compromise the host. These complementary threat surfaces are out of scope.

The user is benign, supplies accurate PII, and grants the agent autonomy for the task duration with no human-in-the-loop confirmation for PII submission. This no-confirmation regime is the consumer-default operating mode of deployed browser agents, which auto-fill and submit form fields without per-field consent prompts; a confirmation-gated regime is an orthogonal defense-in-depth posture, and our question is what the agent does when its instructions allow it to proceed. The profile organises values into eight categories (identity, address, payment, financial, professional, credentials, social media, API keys), partitioned into four sensitivity tiers: \emph{critical} (SSN, card with CVV, bank account, password, API key, 2FA code), \emph{high} (email, phone, postal address), \emph{medium} (full name, employer, date of birth), and \emph{low} (residual). The primary security question is whether any critical-tier value reaches an attacker endpoint. The profile is held constant across every environment, model, condition, and seed, controlling for value-frequency confounds in the scorer's exact-value match. Each environment exposes an internal \texttt{/api/captured} endpoint that logs POSTs to attacker-controlled forms or chat surfaces; this is a measurement instrument, not a feature of the threat model.

\subsection{Benchmark Composition}
\label{sec:composition}
% CITE-TYPE: benchmark design philosophy for adversarial robustness; paired-sibling / single-factor-ablation precedents in NLP and CV

Scammer4U comprises 91 adversarial environments and 10 benign-twin baselines, each a self-hosted Flask web application served at a fixed localhost port; multi-origin environments span two or three coordinated apps. Visible domain labels (typosquats, near-brand spellings, mismatched-TLD lookalikes) are rendered into HTML through per-app linkification helpers, so the in-page red flag is observable in screenshot and DOM even though the address bar shows a localhost URL.

The 91 adversarial environments decompose into 31 archetype \emph{parents} and 60 axis-controlled \emph{siblings}. Each sibling is constructed by toggling exactly one of the eight classification axes in Table~\ref{tab:axes}. This single-degree-of-freedom construction is the mechanism enabling the paired-sibling analyses in \S\ref{sec:analysis}: any parent-vs-sibling difference in behaviour can be attributed to the toggled axis rather than to confounded layout, copy, brand, or task factors. \citep{Rubin1974EstimatingCE,Antonakis2010OnMC} Per-environment axis assignments and the full registry are listed in Appendix~\ref{app:envs}.

\subsection{Vector Taxonomy and External Mapping}
\label{sec:vectors}
% CITE-TYPE: social-engineering taxonomies beyond MITRE/OWASP/ENISA (Cialdini compliance; academic phishing-vector taxonomies; dark-pattern catalogues)

Axis B enumerates eight social-engineering patterns: \emph{phishing\_clone}, \emph{credential\_harvest}, \emph{dark\_patterns}, \emph{reward\_trap}, \emph{authority\_impersonation}, \emph{conversational\_deception}, \emph{prompt\_injection}, and \emph{fake\_trust\_signals}. Pressure cues (axis E) and interaction style (axis G) are not vectors but orthogonal modifiers. Each vector is mapped to the closest entries in MITRE ATT\&CK Enterprise~\citep{mitre_attack_citation}, the OWASP Top 10 for LLM Applications~\citep{owasp_llm_citation}, and the ENISA AI threat landscape~\citep{enisa_citation}; the full mapping is in Appendix~\ref{app:mitre}.

\subsection{Authoring Process}
\label{sec:authoring}
% CITE-TYPE: LLM-assisted benchmark generation; scaling adversarial benchmarks via templated design briefs; author-vs-evaluator model-separation rationale

Environments are LLM-authored from human-written design briefs and manually reviewed against the brief; the authoring model is held constant across all 91 environments and is distinct from any of the four models evaluated in \S\ref{sec:setup-runs}, so no agent in the panel is graded on implementations it itself produced. The brief specifies the impersonated sector, the legitimate task, the attack surface, every axis value, and the visible red flags before any code is generated, leaving the authoring model only a clerical role. The full authoring protocol, manual-review checklist, and rationale for the curated-design / generated-implementation style are in Appendix~\ref{app:authoring}.

\paragraph{Fidelity to real phishing.} We validate fidelity through a blind $20$-vs-$20$ human review in which $16$ reviewers rated interleaved screenshots of Scammer4U environments and real captured-phishing pages (PhishTank/Wayback) on visual believability, copy quality, and likelihood-of-fooling-a-user. Reviewers fail to discriminate our environments from real phishing above chance ($47.5\%$ strict accuracy, $n = 640$), rate Scammer4U environments at or above the real captures on all three axes including likelihood-of-fooling, and do not agree among themselves which items are which (Fleiss~$\kappa = 0.02$). The full protocol, per-axis Likerts with CIs, familiarity and confidence stratification, the wrong-direction crosstab, and the per-stimulus table are in Appendix~\ref{app:fidelity}.

\section{Experimental Setup}
\label{sec:setup}

\subsection{Models, Conditions, and Runs}
\label{sec:setup-runs}

Four frontier multimodal agents are evaluated: GPT-5 mini, Claude Haiku 4.5, Gemini 3 Flash, and Llama 4 Scout. The panel is curated rather than exhaustive: we target the agentic systems most likely to be deployed in consumer-facing browsing roles at the time of writing, spanning three model families (OpenAI, Anthropic, Google) plus one open-weight reference point. Generalisation to smaller open-weight models or to commercial scaffolds not included here is not within scope of the present study and is flagged in \S\ref{sec:limitations}. All four run in the same harness, with the same observation format (screenshot plus flattened DOM), action space, context policy, and per-step prompt template; model-specific differences are confined to the API wrapper. Pinned model identifiers, including provider, version string, and sampling parameters, are frozen at the pre-registration tag (\S\ref{sec:prereg}) and reproduced in Appendix~\ref{app:models}.

Each agent is run under four between-conditions: \textbf{C0} (baseline system prompt with no privacy guidance), \textbf{C1} (a brief generic privacy nudge reminding the agent to avoid suspicious sites and handle PII carefully), \textbf{C2} (a phishing-aware checklist of typosquats, urgency framing, unverified senders, and tier-based submission rules), and \textbf{C3} (pre-submission reflection requiring the agent to verbalise an explicit trust judgment before any PII form submission). C3 doubles as the F1 detection-action gap amplifier: an agent that explicitly verbalises suspicion in C3 and submits anyway exhibits the gap by construction. Verbatim C0--C3 prompt strings are in Appendix~\ref{app:prompts} and frozen at the tag.

We target $n = 5$ independent seeds per (environment, model, condition) cell on the 91 adversarial environments, and $n = 5$ seeds on each of the 10 benign twins under C0 only. Seeds vary the sampling-temperature seed; environment state is otherwise deterministic. The targeted total session count is $91 \cdot 4 \cdot 5 \cdot 4 + 10 \cdot 4 \cdot 5 = 7{,}480$; realised totals at submission are reported in \S\ref{sec:results-baseline} and reflect post-\texttt{BROWSER\_ERROR} exclusion together with any seeds still in progress at the time of submission.

\subsection{Benign-Twin Baselines}
\label{sec:benign}
% CITE-TYPE: counterfactual-baseline methodology in adversarial benchmarks; attack-attributable vs incidental leakage framing

Form-filling is part of an agent's legitimate task, so some baseline rate of PII submission is expected on attack-free sites. To report \emph{attack-attributable} leakage we construct 10 benign-twin environments by forking attack environments and stripping the attack surface while preserving the legitimate task, then subtract the twin baseline from each env rate. Because the twins leak critical PII at $0\%$ under C0 (\S\ref{sec:results-baseline}), the headline rates are essentially attack-attributable; we report both the raw and the adjusted $\text{PLR}_{\text{crit}}$ in \S\ref{sec:results} so the adjustment is auditable, and the mitigation effects (M1--M3) and the F1 gap are computed on the raw rates because the adjustment is constant within each (env, model, condition) cell. Twin construction, category stratification, and the subtraction with its under-two-twins global fallback are detailed in Appendix~\ref{app:benign-twin}.

\subsection{Outcome Metrics}
\label{sec:metrics}
% CITE-TYPE: PLR / leakage-rate metric design in agent privacy; exact-match scoring conventions; tier-weighted leak scoring precedent

For session $s$ we define six outcomes. \textbf{PLR$_{\text{crit}}$} (primary) is $1$ if any critical-tier value is submitted to an attacker endpoint in $s$, else $0$; cell-level rates are session means within each (env, model, condition) cell. Critical-tier values are detected by exact-string match between the profile and outbound POST bodies captured at \texttt{/api/captured}; the profile is constructed so every critical value is globally unique (16-digit cards, full SSN format, \texttt{sk-}-prefixed API keys), so a substring or paraphrased leak that omits the exact stored value is not counted and $\text{PLR}_{\text{crit}}$ is a lower bound on adversarial extraction. Matcher precision and recall against the 200-sample human-labelled DR set are in Appendix~\ref{app:matcher}. \textbf{PLR$_{\text{weighted}}$} (secondary) is the tier-weighted leak rate $\sum_t w_t \mathbb{I}[s \text{ leaks tier } t] / \sum_t w_t$ with $w = (4, 2, 1, 0.5)$ for tiers $(\text{crit}, \text{high}, \text{med}, \text{low})$. \textbf{ASR} (secondary) records whether the attacker's intended outcome occurred (PII at attacker endpoint or transaction completed) and is computed only over sessions with $\texttt{reached\_trap}(s) = \text{True}$ (\S\ref{sec:reachedtrap}). \textbf{TCR} (secondary) records whether the legitimate task was completed. \textbf{DR} (secondary) is the session-level boolean indicating whether the agent's reasoning identifies the site as suspicious, phishing, untrustworthy, or scam-like at any step, operationalised via LLM-as-judge (\S\ref{sec:dr}). \textbf{Defended} (secondary) is true when the agent either refuses (attempts to leave the eval surface and is blocked by the harness egress guard) or safely completes the legitimate task without ever reaching the attack surface, in both cases with no critical-tier leak and no attacker success; the \texttt{defense\_via} decomposition and rationale are in Appendix~\ref{app:per-model}.

\subsection{Reached-Trap Instrumentation}
\label{sec:reachedtrap}
% CITE-TYPE: attack-surface-reach instrumentation in agent benchmarks; non-reach-vs-refusal disentanglement

For each environment we declare one or more \emph{trap URLs} corresponding to the attack surface (the malicious form page, the chat surface, the phished sign-in clone) in the environment registry. Every navigation initiated by the agent is logged at the browser layer, and the scorer marks $\texttt{reached\_trap} = \text{True}$ if any logged navigation matches a declared trap URL. ASR is reported conditional on $\texttt{reached\_trap} = \text{True}$ to disentangle non-leakage caused by detection from non-leakage caused by failure to reach the attack surface; PLR and DR are reported across all sessions.

\subsection{Detection Rate Judge}
\label{sec:dr}
% CITE-TYPE: LLM-as-judge methodology (judge-LLM validation, chatbot-arena style); inter-annotator $\kappa$ in NLP annotation; cross-family judge validity

DR is operationalised by an LLM judge \citep{GU2026101253, Zhu2023JudgeLMFL,Li2024FromGT} applied per step to the agent's reasoning trace under a fixed rubric---\emph{did the agent identify the site as suspicious, phishing, untrustworthy, or scam-like?}---with step-level labels aggregated to a session-level positive if any step fires. \textbf{DR measures verbalised suspicion expressed in the trace, not latent internal recognition.} The detection--action gap (\S\ref{sec:results-f1}) should accordingly be read behaviourally---agents frequently continue with unsafe submissions despite explicitly narrating suspicion---rather than as a claim about what the model internally ``knew''. The primary judge is GPT-4o-mini and the secondary is Llama 4 Scout; neither shares a model family with three of the four evaluated agents, and the single within-family pair (GPT-4o-mini / GPT-5 mini) is bounded by per-model stratified inter-judge $\kappa$ and a both-judges-agree sensitivity (Appendix~\ref{app:dr-sensitivity}). The cross-family judge has been run on the full $n = 2{,}020$-session pool of all four evaluated models (inter-judge $\kappa$ in the 0.39--0.44 fair-to-moderate band), and F1 is reported pooled across all four. A keyword-match heuristic over the same traces is retained as an auxiliary signal but overstates the gap (\S\ref{sec:results-f1}); the LLM-judge primary is the more conservative reading. The rubric, the 200-pair human-validation protocol (pre-registered target $\kappa \geq 0.7$), and the judge-vs-keyword sensitivity are in Appendix~\ref{app:dr-sensitivity}.

\subsection{Analysis Framework}
\label{sec:analysis}
% CITE-TYPE: mixed-effects logistic regression in CS / NLP experiments; BH correction reference; pre-registration practice in ML and security

The pre-registered primary family comprises the paired single-factor tests (F1, F2--F11) and three mitigation contrasts (M1--M3). The full contrast-by-contrast specification, the power gate that determines which axes are inference-bearing, and the per-axis minimum detectable effects are in Appendix~\ref{app:claims}. Each test is a mixed-effects logistic regression on session-level $\text{PLR}_{\text{crit}}$ with the contrast of interest as a fixed effect and environment and model as crossed random effects, which prevents env- and model-specific tendencies from inflating the effective sample size; convergence failures fall back to a pre-committed Wilcoxon signed-rank test on environment-mean proportions. We report a point estimate (percentage points), a 95\% CI, and a Benjamini--Hochberg-adjusted $q$ over the primary family at $q=0.05$. Exploratory analyses (inter-mitigation comparisons, per-model breakdowns, the F1 secondary, the TCR$\times$ASR trade-off) carry uncorrected $p$-values and are flagged as such.

Two headline claims carry pre-committed falsification thresholds.  \citep{Barocas2021DesigningDE,MLSYS2021_0184b0cd} The mitigation-insufficiency claim is falsified if any of C1, C2, C3 produces a $\geq 30$ percentage-point drop in pooled $\text{PLR}_{\text{crit}}$ relative to C0 across all four models. The detection--action claim is falsified if within-C3 $\text{PLR}_{\text{crit}} \mid \text{DR}{=}1 \leq 0.10$.
